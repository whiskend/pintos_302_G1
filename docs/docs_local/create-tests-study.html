SYS_CREATE 테스트 해석

Pintos Project 2의 create(file, initial_size) 관련 테스트가 무엇을 확인하는지 정리한 문서입니다. create는 파일을 새로 만들고 성공 여부를 반환하며, fd table에 파일을 등록하지 않습니다.

핵심 흐름

유저 wrapper create(const char *file, unsigned initial_size)는 파일 이름 문자열 포인터와 초기 크기를 커널에 넘깁니다. 커널의 SYS_CREATE는 이 두 인자를 읽고 filesys_create(file_name, initial_size)를 호출합니다.

중요: filesys_create()는 struct file *을 반환하지 않습니다. 반환값은 생성 성공 여부인 bool입니다. 따라서 create는 fd table을 건드리지 않습니다.

테스트 요약

테스트 소스가 하는 일 .ck 기대/허용 결과 구현 관점
create-normal create("quux.dat", 0) 호출 성공 메시지 후 exit(0) 정상 파일 이름과 크기 0으로 파일 생성이 성공해야 함
create-exists 여러 파일을 만들고 같은 이름을 다시 생성 시도 기존 이름 재생성은 실패해야 전체 CHECK 통과 이미 존재하는 파일 이름에 대해 false 반환 필요
create-empty create("", 0) 호출 0 반환 후 정상 종료 또는 exit(-1) 허용 빈 문자열을 실패 처리해야 함. 조용히 false가 가장 자연스러움
create-long 512바이트짜리 긴 이름으로 생성 시도 create("x..."): 0, exit(0) 너무 긴 파일 이름은 생성 실패로 false 반환
create-null create(NULL, 0) 호출 exit(-1) 파일 이름 포인터가 NULL이면 프로세스 종료
create-bad-ptr create((char *) 0x20101234, 0) 호출 exit(-1) 잘못된 유저 포인터를 커널이 직접 읽다가 panic 나면 안 됨
create-bound 파일 이름 문자열이 두 페이지 경계를 걸치도록 배치됨 create("quux.dat"): 1, exit(0) 문자열이 페이지 경계를 넘어도 모두 유효하면 성공해야 함

인자 해석

  • f->R.rdi: 파일 이름 문자열 포인터
  • f->R.rsi: 초기 파일 크기
  • f->R.rax: filesys_create()의 성공 여부
헷갈리기 쉬운 점: wrapper의 인자 이름이 file이라도 타입은 const char *입니다. 이것은 struct file *이 아니라 파일 이름 문자열입니다.

포인터 검증 포인트

create-null, create-bad-ptr, create-bound는 파일 이름 문자열 포인터 검증을 확인합니다. 시작 주소만 검사하면 부족하고, 문자열 끝의 '\0'을 만날 때까지 유효한 유저 주소인지 확인해야 합니다.

  • NULL은 실패 또는 종료 대상입니다. 이 테스트에서는 exit(-1)가 기대됩니다.
  • 커널 주소 또는 매핑되지 않은 유저 주소를 읽으면 안 됩니다.
  • 페이지 경계를 넘는 문자열은 유효한 페이지들이라면 허용해야 합니다.

체크리스트

  • SYS_CREATE는 fd table에 entry를 추가하지 않는다.
  • 파일 이름은 rdi, 초기 크기는 rsi에서 읽는다.
  • filesys_create()의 bool 반환값을 rax에 넣는다.
  • 빈 이름과 긴 이름은 실패 반환으로 처리할 수 있어야 한다.
  • 나쁜 포인터는 커널 panic 없이 프로세스를 종료시켜야 한다.
