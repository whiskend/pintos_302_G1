# Pintos Project 2 학습 문서: 인자 전달 Argument Passing 쉽게 이해하기

## 0. 한 줄 요약

**인자 전달이란 Pintos 커널이 사용자 프로그램을 시작하기 전에 `argc`, `argv`를 제대로 만들어서 사용자 프로그램에게 넘겨주는 작업이다.**

예를 들어 사용자가 이렇게 실행했다고 해보자.

```bash
/bin/ls -l foo bar
```

사용자 프로그램 입장에서는 이렇게 받아야 한다.

```c
int main(int argc, char *argv[])
```

그리고 값은 이렇게 되어야 한다.

```text
argc = 4

argv[0] = "/bin/ls"
argv[1] = "-l"
argv[2] = "foo"
argv[3] = "bar"
argv[4] = NULL
```

Pintos 프로젝트 2에서 해야 할 일은 **이 모양을 커널이 직접 만들어주는 것**이다.

---

# 1. 먼저 전체 흐름부터 보기

사용자가 프로그램을 실행하면 커널은 이런 일을 해야 한다.

```text
명령어 문자열 받기
        ↓
공백 기준으로 단어 나누기
        ↓
첫 번째 단어를 실행 파일 이름으로 사용
        ↓
나머지 단어들을 프로그램 인자로 준비
        ↓
사용자 스택에 문자열과 argv 배열 만들기
        ↓
rdi에 argc 넣기
        ↓
rsi에 argv 주소 넣기
        ↓
사용자 프로그램 시작
```

예를 들어:

```bash
grep foo bar
```

이 명령어는 이렇게 나뉜다.

```text
argv[0] = "grep"
argv[1] = "foo"
argv[2] = "bar"
argc = 3
```

즉, Pintos 커널은 사용자 프로그램이 시작되기 전에 이런 상태를 만들어야 한다.

```text
rdi = 3
rsi = argv 배열의 시작 주소
```

---

# 2. 왜 이걸 해야 할까?

C 프로그램은 보통 이렇게 시작한다.

```c
int main(int argc, char *argv[]) {
    ...
}
```

여기서 `argc`와 `argv`는 명령줄 인자를 의미한다.

예를 들어 리눅스에서:

```bash
ls -l foo
```

를 실행하면 `main()`은 대략 이렇게 받는다.

```c
argc = 3;
argv[0] = "ls";
argv[1] = "-l";
argv[2] = "foo";
argv[3] = NULL;
```

그런데 Pintos에서는 이걸 자동으로 해주는 완성된 OS가 없다.

그래서 우리가 직접 커널 코드에서 만들어줘야 한다.

즉 프로젝트 2의 인자 전달은 이런 작업이다.

```text
사용자가 입력한 문자열을
사용자 프로그램의 main(argc, argv)가 이해할 수 있는 형태로 바꿔주는 것
```

# 3. 호출 규약 Calling Convention이란?

## 3.1 쉽게 말하면

**호출 규약은 함수를 부를 때 지켜야 하는 약속이다.**

함수를 부를 때 CPU는 아무렇게나 인자를 전달하지 않는다.

예를 들어:

```c
f(1, 2, 3);
```

을 호출하면 x86-64에서는 인자들이 정해진 레지스터에 들어간다.

```text
첫 번째 인자 → rdi
두 번째 인자 → rsi
세 번째 인자 → rdx
네 번째 인자 → rcx
다섯 번째 인자 → r8
여섯 번째 인자 → r9
```

그래서:

```c
f(1, 2, 3);
```

은 CPU 입장에서 대략 이런 상태가 된다.

```text
rdi = 1
rsi = 2
rdx = 3
```

---

# 4. caller와 callee

함수 호출을 이해하려면 두 단어를 알아야 한다.

| 용어     | 뜻         | 예시       |
| ------ | --------- | -------- |
| caller | 함수를 부르는 쪽 | `main()` |
| callee | 호출당한 함수   | `f()`    |

예를 들어:

```c
void f(int a, int b, int c) {
    ...
}

int main(void) {
    f(1, 2, 3);
}
```

여기서:

```text
main = caller
f    = callee
```

즉 `main()`이 `f()`를 부른다.

---

# 5. CALL 명령어는 무슨 일을 할까?

C 코드에서 함수를 부르면 CPU는 내부적으로 `CALL` 명령어를 사용한다.

`CALL`은 두 가지 일을 한다.

```text
1. 함수가 끝난 뒤 돌아올 주소를 스택에 저장한다.
2. 호출할 함수의 시작 위치로 점프한다.
```

예를 들어:

```c
int result = add(10, 20);
printf("%d\n", result);
```

여기서 `add(10, 20)`이 끝나면 다시 어디로 돌아와야 할까?

```c
printf("%d\n", result);
```

이 위치로 돌아와야 한다.

그래서 `CALL`은 `add` 함수로 이동하기 전에 **돌아올 주소**를 스택에 저장한다.

이 돌아올 주소를 **return address**, 즉 **반환 주소**라고 한다.

---

# 6. RET 명령어는 무슨 일을 할까?

함수가 끝나면 `RET` 명령어가 실행된다.

`RET`은 이런 일을 한다.

```text
1. 스택에서 반환 주소를 꺼낸다.
2. 그 주소로 점프한다.
```

즉:

```text
CALL = 돌아올 주소를 저장하고 함수로 들어가기
RET  = 저장된 주소를 꺼내 원래 위치로 돌아가기
```

둘은 한 쌍이다.

---

# 7. 반환값은 어디에 저장될까?

함수가 값을 반환하면 그 값은 보통 `rax` 레지스터에 저장된다.

예를 들어:

```c
int add(int a, int b) {
    return a + b;
}
```

그리고:

```c
int result = add(10, 20);
```

이면 `add()`의 결과는 30이다.

CPU 입장에서는 이렇게 된다.

```text
rax = 30
```

그리고 호출한 쪽은 `rax`에 있는 값을 가져다 사용한다.

# 8. 호출 규약 전체 흐름

예를 들어 이런 함수가 있다고 하자.

```c
void f(int a, int b, int c) {
    ...
}

int main(void) {
    f(1, 2, 3);
}
```

`f(1, 2, 3)`이 호출될 때 CPU 상태는 대략 이렇게 된다.

```text
rdi = 1
rsi = 2
rdx = 3
```

그리고 스택에는 반환 주소가 들어 있다.

```text
stack pointer
     ↓
+----------------+
| return address |
+----------------+
```

즉 `f()`가 실행을 시작할 때는 이런 상태다.

```text
RDI = 1
RSI = 2
RDX = 3
스택 맨 위 = return address
```

# 9. Pintos 사용자 프로그램은 어디서 시작할까?

Pintos의 사용자 프로그램은 직접 `main()`에서 시작하지 않는다.

먼저 `_start()`라는 함수에서 시작한다.

`lib/user/entry.c`에 있는 `_start()`는 이런 모양이다.

```c
void
_start (int argc, char *argv[]) {
    exit (main (argc, argv));
}
```

쉽게 말하면 `_start()`는 `main()`을 감싸는 포장지 같은 함수다.

흐름은 이렇다.

```text
_start(argc, argv)
        ↓
main(argc, argv)
        ↓
main이 반환한 값
        ↓
exit(반환값)
```

즉 사용자 프로그램이 끝나면 자동으로 `exit()`이 호출된다.

---

# 10. 커널은 무엇을 준비해야 할까?

사용자 프로그램이 `_start(argc, argv)`로 시작하려면, 커널은 시작 전에 호출 규약에 맞게 레지스터를 세팅해야 한다.

`_start()`의 인자는 두 개다.

```c
_start(int argc, char *argv[])
```

x86-64 호출 규약에 따르면:

```text
첫 번째 인자 argc → rdi
두 번째 인자 argv → rsi
```

따라서 Pintos 커널은 사용자 프로그램을 시작하기 전에 이렇게 해야 한다.

```text
rdi = argc
rsi = argv 배열의 시작 주소
```

예를 들어:

```bash
/bin/ls -l foo bar
```

라면:

```text
argc = 4
argv = argv[0]의 주소
```

이므로:

```text
rdi = 4
rsi = argv 배열 시작 주소
```

가 되어야 한다.

명령어가 다음과 같다고 하자.

```bash
/bin/ls -l foo bar
```

먼저 공백 기준으로 나눈다.

```text
/bin/ls
-l
foo
bar
```

그러면 `argc`와 `argv`는 이렇게 되어야 한다.

```text
argc = 4

argv[2] = "foo"
argv[3] = "bar"
argv[4] = NULL
```

여기서 중요한 점은 마지막에 `NULL`이 들어간다는 것이다.

```text
argv[argc] = NULL
```

즉:

```text
argv[4] = NULL
```

이 규칙은 C 표준에서 요구하는 형태다.

# 12. 사용자 스택에 무엇을 넣어야 할까?

Pintos는 사용자 프로그램을 시작하기 전에 사용자 스택을 직접 만들어야 한다.

예를 들어:

```bash
/bin/ls -l foo bar
```

라면 스택에는 대략 이런 것들이 들어가야 한다.

```text
문자열들:
"/bin/ls\0"
"-l\0"
"foo\0"
"bar\0"

포인터들:
argv[0] → "/bin/ls"
argv[1] → "-l"
argv[2] → "foo"
argv[3] → "bar"
argv[4] → NULL

가짜 반환 주소:
0
```

스택은 아래쪽으로 자란다.

즉 높은 주소에서 시작해서 데이터를 넣을수록 주소가 낮아진다.

```text
높은 주소
+------------------+
| 문자열들          |
+------------------+
| 정렬용 패딩       |
+------------------+
| argv[4] = NULL   |
| argv[3] 주소      |
| argv[2] 주소      |
| argv[1] 주소      |
| argv[0] 주소      |
+------------------+
| fake return addr |
+------------------+
낮은 주소
```

---

# 13. 왜 문자열을 스택에 넣을까?

`argv`는 문자열 배열이 아니다.

정확히는 **문자열을 가리키는 포인터들의 배열**이다.

```c
char *argv[]
```

즉 `argv[0]` 자체가 문자열 내용을 직접 담는 게 아니다.

```text
argv[0]은 "/bin/ls" 문자열이 있는 주소를 가리킨다.
argv[1]은 "-l" 문자열이 있는 주소를 가리킨다.
argv[2]은 "foo" 문자열이 있는 주소를 가리킨다.
argv[3]은 "bar" 문자열이 있는 주소를 가리킨다.
```

그래서 스택에는 두 종류의 데이터가 필요하다.

```text
1. 실제 문자열
2. 그 문자열들을 가리키는 주소들
```

---

# 14. 왜 argv를 오른쪽에서 왼쪽 순서로 넣을까?

스택은 아래쪽으로 자란다.

즉 데이터를 넣을 때마다 주소가 감소한다.

예를 들어 포인터들을 넣는다고 하자.

우리가 최종적으로 원하는 모양은 이렇다.

```text
낮은 주소
argv[0]
argv[1]
argv[2]
argv[3]
argv[4] = NULL
높은 주소
```

그래야 `argv`가 `argv[0]`을 가리키고, 그 다음 메모리에 `argv[1]`, `argv[2]`가 이어진다.

스택에 push를 하면 주소가 낮아지기 때문에, 원하는 순서를 만들려면 뒤에서부터 넣어야 한다.

```text
먼저 NULL
그 다음 argv[3]
그 다음 argv[2]
그 다음 argv[1]
마지막으로 argv[0]
```

그래야 최종적으로 `argv[0]`이 가장 낮은 주소에 놓인다.

---

# 15. 왜 스택 정렬이 필요할까?

문서에서는 첫 번째 push 전에 스택 포인터를 8의 배수로 맞추라고 한다.

이것을 **word alignment**, 즉 **단어 정렬**이라고 한다.

쉽게 말하면 CPU가 데이터를 더 빠르고 안정적으로 읽기 위해 주소를 깔끔한 단위에 맞추는 것이다.

예를 들어 8바이트 단위로 정렬하면 주소가 이런 식이어야 한다.

```text
0x...ff08
0x...ff00
0x...fff8
0x...fff0
```

반대로 이런 주소는 8의 배수가 아니다.

```text
0x...fff5
0x...ffed
```

문자열 자체는 꼭 8바이트 정렬일 필요가 없지만, 포인터를 push하기 전에는 스택 주소를 8의 배수로 맞추는 것이 좋다.

# 16. 왜 가짜 반환 주소를 넣을까?

일반 함수 호출에서는 `CALL` 명령어가 반환 주소를 자동으로 스택에 넣는다.

하지만 Pintos에서 사용자 프로그램을 시작할 때는 일반적인 `CALL`로 `_start()`를 부르는 게 아니다.

커널이 레지스터와 스택을 직접 준비한 다음, 사용자 모드로 넘어간다.

그래서 스택 모양을 일반 함수 호출처럼 보이게 만들기 위해 가짜 반환 주소를 넣는다.

보통 값은 0이다.

```text
fake return address = 0
```

`_start()`는 실제로 반환하지 않는다.

왜냐하면 `_start()`는 이렇게 생겼기 때문이다.

```c
void
_start (int argc, char *argv[]) {
    exit (main (argc, argv));
}
```

`main()`이 끝나면 `exit()`을 호출하므로 `_start()`가 일반 함수처럼 돌아올 일이 없다.

그래도 스택 구조를 맞추기 위해 가짜 반환 주소를 넣는다.

# 19. `process_exec()`에서 무엇을 바꿔야 할까?

기존 `process_exec()`는 보통 실행 파일 이름만 처리한다.

하지만 이제는 이런 문자열도 처리해야 한다.

```c
process_exec("grep foo bar");
```

이때 `"grep foo bar"` 전체를 파일 이름으로 보면 안 된다.

잘못된 처리:

```text
실행 파일 이름 = "grep foo bar"
```

올바른 처리:

```text
실행 파일 이름 = "grep"
인자 1 = "foo"
인자 2 = "bar"
```

즉 `process_exec()`는 명령줄을 공백 기준으로 나눠야 한다.

# 20. 여러 개의 공백은 어떻게 처리할까?

다음 두 명령은 같은 의미로 처리해야 한다.

```bash
grep foo bar
```

```bash
grep     foo       bar
```

즉 여러 개의 공백은 하나의 공백처럼 취급한다.

결과는 둘 다 같다.

```text
argv[0] = "grep"
argv[1] = "foo"
argv[2] = "bar"
argc = 3
```

이런 문자열 파싱에는 `strtok_r()`를 사용할 수 있다.

---

# 21. `strtok_r()`는 무엇인가?

`strtok_r()`는 문자열을 특정 구분자를 기준으로 나눠주는 함수다.

예를 들어:

```c
char input[] = "grep foo bar";
char *save_ptr;

char *token = strtok_r(input, " ", &save_ptr);
```

처음 호출하면:

```text
token = "grep"
```

다음 호출에서는 첫 번째 인자로 `NULL`을 넣는다.

```c
token = strtok_r(NULL, " ", &save_ptr);
```

그러면:

```text
token = "foo"
```

다시 호출하면:

```text
token = "bar"
```

다시 호출하면 더 이상 토큰이 없으므로:

```text
token = NULL
```

이걸 반복하면 명령줄을 단어 단위로 나눌 수 있다.

---

# 22. 구현 목표

인자 전달 구현의 최종 목표는 다음과 같다.

```c
process_exec("grep foo bar");
```

이 호출이 들어왔을 때 사용자 프로그램이 다음과 같이 시작해야 한다.

```c
int main(int argc, char *argv[]) {
    // argc == 3
    // argv[0] == "grep"
    // argv[1] == "foo"
    // argv[2] == "bar"
    // argv[3] == NULL
}
```

즉 커널은 다음 상태를 만들어야 한다.

```text
rdi = 3
rsi = argv 배열의 시작 주소
사용자 스택 = 문자열, 포인터, NULL, fake return address 포함
```

---

# 23. 구현 순서

## 23.1 명령줄 복사하기

원본 문자열을 직접 수정하면 위험할 수 있다.

`strtok_r()`는 문자열 안의 공백을 `\0`으로 바꾸면서 파싱하기 때문이다.

따라서 명령줄을 복사해서 사용하는 것이 좋다.

```text
원본: "grep foo bar"
복사본: "grep foo bar"
```

복사본을 파싱해서 다음처럼 만든다.

```text
"grep\0foo\0bar\0"
```

---

## 23.2 명령줄을 단어로 나누기

```text
"grep foo bar"
        ↓
"grep", "foo", "bar"
```

결과:

```text
argv[0] = "grep"
argv[1] = "foo"
argv[2] = "bar"
argc = 3
```

---

## 23.3 첫 번째 단어로 실행 파일 로드하기

`load()`는 실행 파일 이름을 받아야 한다.

따라서:

```text
load("grep", ...)
```

처럼 첫 번째 단어만 넘겨야 한다.

잘못된 예:

```text
load("grep foo bar", ...)
```

올바른 예:

```text
load("grep", ...)
```

---

## 23.4 문자열들을 사용자 스택에 복사하기

각 인자 문자열을 사용자 스택에 복사한다.

예:

```text
"grep\0"
"foo\0"
"bar\0"
```

복사하면서 각 문자열이 들어간 주소를 저장해둔다.

```text
arg_addr[0] = "grep"이 저장된 주소
arg_addr[1] = "foo"가 저장된 주소
arg_addr[2] = "bar"가 저장된 주소
```

나중에 `argv[0]`, `argv[1]`, `argv[2]`에 이 주소들을 넣어야 하기 때문이다.

---

## 23.5 스택 정렬 맞추기

포인터를 넣기 전에 스택 포인터를 8의 배수로 맞춘다.

개념적으로는 이런 작업이다.

```text
while rsp % 8 != 0:
    rsp를 1 감소시키고 0을 넣기
```

---

## 23.6 `argv[argc] = NULL` 넣기

C 표준에서는 `argv`의 마지막이 `NULL`이어야 한다.

예:

```text
argv[0] = "grep"
argv[1] = "foo"
argv[2] = "bar"
argv[3] = NULL
```

따라서 스택에 먼저 NULL 포인터를 넣는다.

---

## 23.7 argv 포인터들을 넣기

그다음 문자열 주소들을 오른쪽에서 왼쪽 순서로 넣는다.

예:

```text
argv[2] 주소
argv[1] 주소
argv[0] 주소
```

스택은 아래쪽으로 자라기 때문에 이렇게 넣어야 최종적으로 `argv[0]`이 가장 낮은 주소에 놓인다.

---

## 23.8 `rsi`에 argv 주소 넣기

`argv[0]`이 저장된 위치가 곧 `argv` 배열의 시작 주소다.

따라서 그 주소를 `rsi`에 넣는다.

```text
rsi = argv 배열 시작 주소
```

---

## 23.9 fake return address 넣기

마지막으로 가짜 반환 주소 0을 스택에 넣는다.

```text
fake return address = 0
```

---

## 23.10 `rdi`에 argc 넣기

`argc`는 첫 번째 인자이므로 `rdi`에 넣는다.

```text
rdi = argc
```

---

# 24. 최종 상태 체크

예를 들어:

```bash
grep foo bar
```

이면 사용자 프로그램 시작 직전 상태는 이렇게 되어야 한다.

```text
rdi = 3
rsi = argv 배열 시작 주소
rsp = fake return address 위치
```

그리고 스택에는:

```text
"grep\0"
"foo\0"
"bar\0"
정렬 패딩
NULL
주소 of "bar"
주소 of "foo"
주소 of "grep"
fake return address
```

가 들어 있어야 한다.

---

# 25. 초보자용 비유

인자 전달은 **여행 가방 싸기**와 비슷하다.

사용자 프로그램이 여행을 떠나기 전에 커널이 가방을 싸준다.

```text
문자열들 = 옷, 세면도구, 충전기
argv 배열 = 물건 목록표
argc = 물건 개수
rdi = 물건 개수를 적은 칸
rsi = 물건 목록표가 있는 위치
스택 = 여행 가방
```

프로그램은 시작하자마자 이렇게 묻는다.

```text
내가 받은 인자가 몇 개지?        → argc
각 인자는 어디 있지?             → argv
첫 번째 인자는 뭐지?              → argv[0]
두 번째 인자는 뭐지?              → argv[1]
```

커널이 가방을 잘못 싸면 사용자 프로그램은 이상한 값을 읽게 된다.

---

# 26. 왜 이게 어려운가?

인자 전달이 헷갈리는 이유는 단순히 문자열을 나누는 문제가 아니기 때문이다.

해야 할 일이 여러 개 섞여 있다.

```text
문자열 파싱
실행 파일 이름 분리
사용자 스택 조작
포인터 주소 저장
스택 정렬
레지스터 설정
호출 규약 이해
```

즉 `argv`를 만드는 일은 단순 배열 생성이 아니라, **사용자 프로그램이 실행될 때 CPU와 메모리가 기대하는 모양을 커널이 직접 만들어주는 작업**이다.

---

# 27. 자주 헷갈리는 부분

## 27.1 `argv[0]`은 첫 번째 인자인가?

보통 `argv[0]`은 프로그램 이름이다.

예:

```bash
grep foo bar
```

이면:

```text
argv[0] = "grep"
argv[1] = "foo"
argv[2] = "bar"
```

따라서 `"foo"`는 첫 번째 실제 인자처럼 보이지만, `argv` 배열에서는 `argv[1]`이다.

---

## 27.2 `argc`는 실제 인자 개수만 세는가?

아니다.

`argc`는 `argv[0]`까지 포함해서 센다.

```bash
grep foo bar
```

이면:

```text
argc = 3
```

왜냐하면:

```text
argv[0] = "grep"
argv[1] = "foo"
argv[2] = "bar"
```

총 3개이기 때문이다.

---

## 27.3 `argv[argc]`는 왜 NULL인가?

프로그램이 `argv`를 순회할 때 끝을 알 수 있게 하기 위해서다.

예:

```c
for (int i = 0; argv[i] != NULL; i++) {
    ...
}
```

이 코드가 가능하려면 마지막에 반드시 `NULL`이 있어야 한다.

---

## 27.4 왜 `rdi`, `rsi`를 직접 설정해야 하는가?

사용자 프로그램의 시작 함수 `_start()`는 이렇게 생겼다.

```c
_start(int argc, char *argv[])
```

x86-64 호출 규약에서 첫 번째 인자는 `rdi`, 두 번째 인자는 `rsi`로 전달된다.

따라서 커널이 직접:

```text
rdi = argc
rsi = argv
```

를 설정해야 한다.

---

## 27.5 왜 fake return address가 필요한가?

일반 함수 호출에서는 `CALL`이 반환 주소를 넣어준다.

하지만 사용자 프로그램 시작은 `CALL`로 하는 것이 아니다.

Pintos 커널이 직접 사용자 모드로 넘어간다.

그래서 일반 함수 호출처럼 보이는 스택 모양을 맞추기 위해 0을 넣는다.

---

# 28. 구현 체크리스트

인자 전달을 구현한 뒤 다음 항목을 확인하면 좋다.

| 체크 항목                     | 설명                                            |
| ------------------------- | --------------------------------------------- |
| 명령줄을 공백 기준으로 나눴는가         | `"grep foo bar"` → `"grep"`, `"foo"`, `"bar"` |
| 여러 공백을 하나처럼 처리하는가         | `"grep    foo"`도 정상 처리                        |
| 첫 번째 단어만 실행 파일 이름으로 사용하는가 | `load("grep")`                                |
| `argc` 값이 올바른가            | `grep foo bar`이면 3                            |
| `argv[0]`이 프로그램 이름인가      | `argv[0] = "grep"`                            |
| 문자열을 사용자 스택에 복사했는가        | 커널 스택이 아니라 사용자 스택                             |
| 문자열 주소들을 저장했는가            | 나중에 argv 배열에 넣기 위해 필요                         |
| `argv[argc] = NULL`을 넣었는가 | 마지막 센티널                                       |
| 포인터들을 올바른 순서로 넣었는가        | 오른쪽에서 왼쪽 순서                                   |
| 스택 정렬을 맞췄는가               | 8바이트 정렬                                       |
| fake return address를 넣었는가 | 보통 0                                          |
| `rdi = argc`로 설정했는가       | 첫 번째 인자                                       |
| `rsi = argv`로 설정했는가       | 두 번째 인자                                       |
| 최종 `rsp`가 올바른 위치인가        | fake return address 위치                        |

---

# 31. 최종 요약

인자 전달은 다음을 구현하는 작업이다.

```text
"grep foo bar"
        ↓
argv[0] = "grep"
argv[1] = "foo"
argv[2] = "bar"
argv[3] = NULL
argc = 3
        ↓
사용자 스택에 문자열과 포인터 배치
        ↓
rdi = argc
rsi = argv
        ↓
사용자 프로그램 시작
```

핵심은 이것이다.

**Pintos 커널은 사용자 프로그램이 `_start(argc, argv)`로 정상 시작한 것처럼 보이도록, 스택과 레지스터를 직접 꾸며줘야 한다.**
