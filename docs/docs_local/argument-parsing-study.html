Argument Parsing

Pintos user program이 시작될 때 커맨드라인 문자열을 잘라서 argc, argv, 사용자 스택으로 넘겨주는 작업을 정리한 공부 노트입니다.

한 줄 개념

Argument parsing은 커널이 받은 문자열, 예를 들면 "args-multiple some arguments for you!"를 프로그램 이름과 인자로 나누고, 새 유저 프로세스의 초기 스택을 C 프로그램의 main(int argc, char *argv[])가 기대하는 모양으로 만드는 일입니다.

핵심 목표: 유저 프로그램이 시작하자마자 argv[0]은 실행 파일 이름, argv[1]부터는 인자 문자열, argv[argc]는 NULL을 읽을 수 있어야 합니다.

어디에서 구현하나

관련 파일

  • pintos/userprog/process.c
  • process_exec(): 커맨드라인 문자열을 받고 load() 호출
  • load(): 실행 파일 로드 후 if_->rip, if_->rsp 설정
  • setup_stack(): 유저 스택으로 쓸 4KB 페이지 하나를 만들고 if_->rsp를 맨 위로 설정

현재 코드 흐름

process_exec(f_name)
  - file_name = f_name
  - process_cleanup()
  - load(file_name, &_if)
      - filesys_open(file_name)
      - setup_stack(&_if)
      - if_->rip = ehdr.e_entry
      - TODO: argument passing
  - do_iret(&_if)
주의: filesys_open()에는 전체 문자열이 아니라 실행 파일 이름만 들어가야 합니다. "args-single onearg" 그대로 열면 그런 이름의 파일이 없어서 로드가 실패합니다.

유저 스택이 뭐야?

유저 스택은 유저 프로그램이 함수 호출, 지역 변수, 함수 인자, 반환 주소 등을 저장하려고 쓰는 메모리 공간입니다. Pintos에서 커널은 새 유저 프로그램을 실행하기 직전에 이 스택을 직접 만들어 줍니다.

예를 들어 유저 프로그램 args.c의 main(int argc, char *argv[])가 시작될 때, argc와 argv는 원래부터 마법처럼 존재하는 값이 아닙니다. 커널이 유저 스택에 문자열과 포인터 배열을 배치하고, CPU 레지스터에 시작 인자를 넣어줘야 유저 프로그램이 argv[0], argv[1]을 읽을 수 있습니다.

커널 스택

  • 커널 코드가 쓰는 스택입니다.
  • load() 안의 지역 변수 char *argv[10] 같은 값이 여기에 놓입니다.
  • 유저 프로그램은 여기에 접근하면 안 됩니다.

유저 스택

  • 유저 프로그램이 실행 중에 쓰는 스택입니다.
  • setup_stack()이 USER_STACK - PGSIZE부터 USER_STACK까지 4KB를 매핑합니다.
  • args.c가 읽을 argv 문자열과 포인터는 여기에 있어야 합니다.
중요: if_->R.rsi = argv처럼 커널 지역 배열 주소를 넘기면 안 됩니다. 그 주소는 커널 스택 주소라서 유저 프로그램 입장에서는 올바른 argv가 아닙니다. if_->R.rsi에는 유저 스택 안에 만든 argv 배열의 주소를 넣어야 합니다.

초기 스택 모양

x86-64 Pintos에서 유저 스택은 높은 주소 USER_STACK 근처에서 시작해 아래 방향으로 자랍니다. 구현할 때는 문자열을 먼저 아래쪽에 복사하고, 그 문자열들의 주소를 다시 스택에 쌓습니다.

높은 주소USER_STACK
argument strings"you!\0", "for\0", ...
word align padding8-byte 정렬
argv[argc]NULL sentinel
argv pointers&"args", &"onearg"
fake return address0
registersRDI = argc, RSI = argv
낮은 주소최종 if_->rsp
64비트 포인트: 이 프로젝트의 user program 시작 규약은 보통 argc를 if_->R.rdi, argv를 if_->R.rsi에 넣고, if_->rsp는 8바이트 정렬 상태로 맞춥니다. 여기서 if_는 struct intr_frame *, 즉 포인터이므로 코드에서는 .이 아니라 ->로 접근합니다. 만약 지역 변수 struct intr_frame _if에 직접 접근할 때만 _if.rsp처럼 .을 씁니다.

구현 순서

용어 먼저: 커맨드라인 원본은 Pintos가 받은 전체 문자열입니다. 예를 들면 "args-single onearg"입니다. 버퍼는 그 문자열을 안전하게 복사해 둔 임시 메모리입니다. 원본 페이지는 보통 palloc_get_page()로 받은 4KB짜리 커널 메모리 한 장을 뜻합니다. 이 페이지는 process_exec()나 load()가 끝나면서 해제될 수 있으므로, 유저 프로그램이 계속 읽어야 하는 인자 문자열은 반드시 유저 스택 쪽에 다시 복사해야 합니다.
  1. 커맨드라인 원본, 예를 들면 "args-single onearg"를 별도 버퍼에 복사합니다. 토큰을 자르는 과정에서 문자열 내용이 바뀔 수 있기 때문입니다.
  2. strtok_r() 같은 재진입 가능한 토크나이저로 공백 기준 토큰을 나눕니다.
  3. 첫 토큰만 실행 파일 이름으로 사용해서 filesys_open()에 넘깁니다.
  4. 스택 페이지, 즉 유저 프로세스의 스택으로 매핑된 4KB 메모리 한 장을 준비합니다. 이 작업은 보통 setup_stack()이 합니다.
  5. 각 인자 문자열을 마지막 인자부터 스택 페이지 안으로 복사합니다. 예를 들면 "onearg\0", "args-single\0" 순서로 아래쪽 주소에 넣습니다.
  6. 문자열 주소들을 배열에 저장해두고, argv[argc] = NULL부터 스택에 쌓습니다.
  7. argv[0]부터 접근 가능하도록 포인터들을 스택에 배치합니다.
  8. if_->R.rdi = argc, if_->R.rsi = argv 주소, if_->rsp = 최종 스택 포인터를 설정합니다. if_가 포인터라서 ->를 씁니다.
자주 터지는 부분: 공백이 두 개 이상일 때 빈 문자열을 인자로 세면 안 됩니다. args-dbl-space는 이 실수를 잡는 테스트입니다.

테스트가 보는 것

모든 args-* 테스트는 같은 소스인 pintos/tests/userprog/args.c를 씁니다. 이 프로그램은 argc, argv[i], argv[argc] == NULL, 그리고 argv 포인터 정렬을 확인합니다. 

if (((unsigned long long) argv & 7) != 0)
  msg("argv and stack must be word-aligned, actually %p", argv);

msg("argc = %d", argc);
for (i = 0; i <= argc; i++)
  if (argv[i] != NULL)
    msg("argv[%d] = '%s'", i, argv[i]);
  else
    msg("argv[%d] = null", i);
테스트 입력 인자 기대 argc 핵심 확인
args-none 없음 1 argv[0] = "args-none", argv[1] = NULL
args-single onearg 2 프로그램 이름 + 인자 하나
args-multiple some arguments for you! 5 여러 인자가 순서대로 보존되는지 확인
args-many a b c ... v 23 인자가 많아도 누락 없이 스택에 올라가는지 확인
args-dbl-space two  spaces! 3 연속 공백을 빈 인자로 취급하지 않는지 확인

args-multiple

(args) begin

스스로 점검하기

테스트 실행 메모

Pintos 빌드 환경에서 userprog 테스트를 돌릴 때는 보통 pintos/userprog/build 아래에서 개별 테스트를 실행합니다. 팀 환경의 Makefile 타깃 이름이 다를 수 있으니, 먼저 기존 프로젝트 안내를 확인하세요. 

cd pintos/userprog
make check TESTS=tests/userprog/args-none
make check TESTS=tests/userprog/args-single
make check TESTS=tests/userprog/args-multiple
make check TESTS=tests/userprog/args-many
make check TESTS=tests/userprog/args-dbl-space

통과 기준은 단순합니다. argc 정확성 argv 순서 NULL sentinel 8-byte alignment 정상 exit
