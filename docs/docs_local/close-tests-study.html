SYS_CLOSE 테스트 해석

Pintos Project 2의 close(fd) 관련 테스트가 무엇을 확인하는지 정리한 문서입니다. close는 fd table에서 entry를 제거하고, 연결된 struct file *을 닫고, entry 메모리를 정리해야 합니다.

핵심 흐름

close는 유저에게 값을 반환하지 않는 syscall입니다. 하지만 내부적으로는 fd table에서 fd entry를 찾고, 그 entry가 잡고 있던 열린 파일을 닫고, fd table에서 제거해야 합니다.

중요: file_close()만 호출하면 충분하지 않습니다. fd table에서 entry를 제거하지 않으면 같은 fd가 계속 유효한 것처럼 보일 수 있고, 동적 할당한 fd entry를 해제하지 않으면 메모리가 남습니다.

테스트 요약

테스트 소스가 하는 일 .ck 기대/허용 결과 구현 관점
close-normal open("sample.txt") 후 그 fd를 close open 메시지, close 메시지 후 exit(0) 정상 fd를 찾아 파일을 닫고 fd table에서 제거해야 함
close-twice 같은 fd를 두 번 close 정상 종료 또는 두 번째 close에서 exit(-1) 허용 첫 close 후 fd가 더 이상 lookup되지 않아야 함
close-bad-fd 큰 invalid fd 0x20101234 close 정상 종료 또는 exit(-1) 허용 없는 fd에서 커널 panic이 나면 안 됨

인자와 반환값

  • f->R.rdi: 닫을 fd 번호
  • close wrapper의 반환 타입은 void
  • file_close()도 반환값이 없는 void 함수
주의: close는 성공 여부를 유저에게 반환하지 않습니다. 따라서 핵심은 반환값이 아니라 "없는 fd에서 안전하게 실패하고, 정상 fd는 다시 lookup되지 않게 만드는 것"입니다.

fd table 관점

close는 fd table을 정리하는 syscall입니다. open이 fd entry를 추가했다면, close는 그 entry를 제거해야 합니다.

  1. fd로 현재 thread의 fd table을 순회한다.
  2. fd가 같은 entry를 찾는다.
  3. 없으면 조용히 실패하거나 exit(-1) 정책을 적용한다.
  4. 있으면 list에서 entry를 제거한다.
  5. file_close(entry->file)로 열린 파일을 닫는다.
  6. free(entry)로 fd entry 메모리를 해제한다.

테스트별 핵심

close-normal

open이 성공해서 fd가 만들어진 뒤, 그 fd를 close할 수 있어야 합니다. 이 테스트는 close 후 파일 내용을 다시 확인하지는 않지만, close 과정에서 panic이 나면 실패합니다.

close-twice

첫 번째 close 후에는 fd table에서 entry가 사라져야 합니다. 두 번째 close는 더 이상 유효한 fd가 아니므로 조용히 무시하거나 exit(-1)로 종료해도 허용됩니다.

close-bad-fd

fd table에 없는 큰 숫자를 넘깁니다. 이 값으로 list나 file API를 잘못 건드리면 안 됩니다.

체크리스트

  • fd lookup 실패 시 file_close(NULL)로 가지 않는다.
  • 정상 close 후 fd entry를 fd table에서 제거한다.
  • 정상 close 후 struct file *을 file_close()로 닫는다.
  • 동적 할당한 fd entry는 free()로 해제한다.
  • 두 번 close해도 커널 panic이 나지 않는다.
