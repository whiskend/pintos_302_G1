SYS_OPEN 테스트 해석

Pintos Project 2의 open(file) 관련 테스트가 무엇을 확인하는지 정리한 문서입니다. open은 파일 이름으로 열린 struct file *을 얻고, fd table에 등록한 뒤 fd 번호를 반환합니다.

핵심 흐름

open은 파일을 새로 만드는 syscall이 아닙니다. 이미 존재하는 파일 이름으로 filesys_open()을 호출하고, 성공하면 반환된 struct file *을 fd table에 저장합니다.

핵심 차이: create는 성공 여부를 반환하지만, open은 성공 시 fd 번호를 반환합니다. fd 번호는 유저 프로그램이 이후 read, write, filesize, close에 넘기는 핸들입니다.

테스트 요약

테스트 소스가 하는 일 .ck 기대/허용 결과 구현 관점
open-normal open("sample.txt") 호출 fd가 2 이상이면 정상 종료 일반 파일 fd는 stdin/stdout 이후 번호여야 함
open-twice 같은 파일을 두 번 open 두 fd 모두 2 이상이고 서로 달라야 함 같은 이름을 여러 번 열면 fd entry도 각각 따로 생겨야 함
open-missing 없는 파일 "no-such-file" open -1 반환 후 정상 종료 filesys_open()이 NULL이면 fd table에 넣지 않음
open-empty 빈 문자열 "" open -1 반환 후 정상 종료 빈 이름은 열 수 없어야 함
open-null open(NULL) 호출 정상 종료 또는 exit(-1) 허용 좋은 구현은 잘못된 포인터에서 exit(-1)
open-bad-ptr open((char *) 0x20101234) 호출 정상 종료 또는 exit(-1) 허용 커널 panic은 금지. 포인터 검증이 필요함
open-boundary 파일 이름 문자열이 두 페이지 경계를 걸침 open "sample.txt" 성공, 정상 종료 페이지 경계를 넘는 문자열도 모두 유효하면 허용해야 함

인자와 반환값

  • f->R.rdi: 파일 이름 문자열 포인터
  • filesys_open(file_name): 성공 시 struct file *, 실패 시 NULL
  • f->R.rax: 성공 시 fd 번호, 실패 시 -1
주의: filesys_open()은 fd 번호를 만들어주지 않습니다. fd 번호 배정, fd entry 생성, fd table 등록은 syscall 구현 쪽 책임입니다.

fd table 관점

open 테스트들은 fd table이 제대로 만들어지는지 가장 먼저 확인합니다. 특히 open-twice는 같은 파일을 두 번 열어도 fd가 서로 달라야 한다는 점을 검사합니다.

  • fd 0은 stdin, fd 1은 stdout이므로 첫 일반 파일 fd는 최소 2입니다.
  • open 성공 시 동적 할당된 fd entry가 필요합니다.
  • fd entry에는 fd 번호와 struct file *이 저장되어야 합니다.
  • fd entry는 현재 thread의 fd_table에 매달려야 합니다.
  • open 실패 시 fd entry를 만들거나 table에 넣으면 안 됩니다.

포인터 검증 포인트

open-null, open-bad-ptr, open-boundary는 파일 이름 문자열 포인터 검증과 관련됩니다. open-boundary는 문자열 시작 주소만 보는 구현을 잡아낼 수 있습니다.

  • 파일 이름 포인터가 NULL인지 확인합니다.
  • 파일 이름 문자열이 유저 주소 범위인지 확인합니다.
  • '\0'을 만날 때까지 모든 접근 주소가 유효한지 봐야 합니다.
  • 페이지 경계를 넘는 문자열은 유효하면 성공해야 합니다.

체크리스트

  • open은 성공 시 fd 번호를 반환한다.
  • 없는 파일과 빈 이름은 -1을 반환한다.
  • 같은 파일을 두 번 열면 서로 다른 fd를 반환한다.
  • 성공한 open만 fd table에 entry를 추가한다.
  • 파일 이름 포인터 검증 실패는 커널 panic으로 이어지면 안 된다.
