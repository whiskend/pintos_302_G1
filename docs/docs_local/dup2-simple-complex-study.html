dup2-simple / dup2-complex 쉽게 이해하기

이 문서는 dup2 테스트가 뭘 확인하는지 쉽게 이해하기 위한 문서다. 구현 코드를 외우기보다, fd가 무엇을 가리켜야 하는지 감을 잡는 게 목표다.

한 줄 요약

dup2(oldfd, newfd)는 newfd가 oldfd와 같은 열린 파일을 가리키게 만드는 syscall이다.

여기서 중요한 건 "같은 파일 이름"이 아니라 같은 열린 파일 상태라는 점이다. 같은 열린 파일 상태를 공유하면, 파일을 어디까지 읽었는지도 같이 공유된다.

fd를 쉽게 생각하기

fd는 파일 자체가 아니다. fd는 현재 프로세스가 들고 있는 번호표다. 

fd 번호  ──>  fd_entry  ──>  열린 파일 상태
이름 쉽게 말하면
fd 사용자 프로그램이 들고 있는 번호
fd_entry fd 번호와 열린 파일을 연결하는 커널 안의 기록
열린 파일 상태 파일 객체와 현재 읽기/쓰기 위치를 가진 상태

open("sample.txt")를 두 번 하면, 같은 파일 이름이어도 보통 서로 다른 열린 파일 상태가 생긴다. 그래서 각 fd의 읽기 위치가 따로 움직인다.

반대로 dup2(fd1, fd2)를 하면, fd1과 fd2는 같은 열린 파일 상태를 같이 본다. 그래서 한쪽에서 읽으면 다른 쪽의 위치도 같이 앞으로 간 것처럼 동작해야 한다.

dup2-simple은 뭘 보는 테스트일까?

dup2-simple은 이름 그대로 가장 작은 핵심만 본다.

  1. sample.txt를 연다.
  2. fd1으로 앞 10바이트를 읽는다.
  3. dup2(fd1, fd2)를 한다.
  4. fd2로 나머지를 읽는다.
  5. 합친 내용이 원래 sample.txt와 같은지 본다.

통과하려면 fd2가 파일 처음부터 읽으면 안 된다. fd1이 이미 10바이트 읽은 위치부터 이어서 읽어야 한다.

왜 실패할 수 있을까?

dup2를 하면서 새로 open하거나 file_reopen처럼 별도 파일 객체를 만들면, fd2의 위치가 처음으로 돌아갈 수 있다. 그러면 앞부분을 중복해서 읽게 되고 테스트가 실패한다.

dup2-complex는 뭘 더 보나?

dup2-complex는 dup2-simple의 확장판이다. 단순히 하나의 fd를 복사하는 것만 보지 않고, 여러 상황을 한 번에 섞어서 확인한다.

확인하는 것 왜 중요한가
seek / tell 파일 위치를 직접 바꾸고 읽어야 한다.
oldfd == newfd dup2(fd, fd)는 아무 것도 망가뜨리면 안 된다.
이미 열린 newfd newfd가 이미 열려 있으면 그 fd만 먼저 닫고 새로 연결해야 한다.
잘못된 fd 음수 fd 같은 invalid fd가 들어와도 기존 fd table을 망가뜨리면 안 된다.
close fd 하나를 닫아도, 같은 열린 파일 상태를 가리키는 다른 fd가 살아 있으면 계속 쓸 수 있어야 한다.
stdout 리다이렉션 dup2(1, fd), dup2(fd, 1)로 출력 방향이 바뀐다.
fork 자식 프로세스가 fd table과 파일 위치를 어떻게 이어받는지도 흔든다.

stdout 리다이렉션이 왜 나오지?

dup2-complex에는 이런 흐름이 나온다. 

dup2(1, fd5);
write(fd5, "Pintos is funny\n", ...);

이 말은 fd5가 stdout과 같은 대상을 가리키게 되었다는 뜻이다. 그래서 write(fd5, ...)가 콘솔 출력처럼 동작해야 한다. 

dup2(fd6, 1);
msg("%d", byte_cnt);

이번에는 반대로 fd 1, 즉 stdout이 파일을 가리키게 된다. 그래서 msg()가 화면에 찍히지 않고 파일에 써질 수 있다.

그래서 write를 단순히 fd == 1이면 콘솔 출력이라고만 구현하면 dup2 이후의 stdout 리다이렉션을 표현하기 어렵다.

ref count가 왜 필요할까?

dup2를 하면 fd 여러 개가 같은 열린 파일 상태를 가리킬 수 있다. 

fd1 ─┐
     ├──> 같은 열린 파일 상태
fd2 ─┘

이때 close(fd1)을 했다고 해서 열린 파일 상태 자체를 바로 닫아버리면 안 된다. 아직 fd2가 그 상태를 쓰고 있기 때문이다.

그래서 "이 열린 파일 상태를 몇 fd가 보고 있는지" 세는 값이 필요하다. 이게 ref count다.

쉽게 말하면:

  • fd가 하나 새로 연결되면 ref count 증가
  • fd가 닫히면 ref count 감소
  • ref count가 0이 될 때만 실제 file_close()

통과하려면 필요한 감각

  • dup2는 fd 번호 복사가 아니라 열린 파일 상태 공유다.
  • oldfd가 틀리면 실패해야 한다.
  • oldfd == newfd이면 아무 것도 바꾸면 안 된다.
  • newfd가 이미 열려 있으면 그 fd만 닫고 다시 연결한다.
  • 같은 열린 파일 상태를 공유하면 file position도 공유된다.
  • fd 하나를 닫아도 다른 fd가 남아 있으면 실제 file은 닫으면 안 된다.
  • stdout도 dup2의 대상이 될 수 있다.
  • seek, tell, read, write는 fd가 가리키는 열린 파일 상태를 기준으로 동작해야 한다.
