# B1/B3 구현용 Pintos 헬퍼 함수 정리

대상 작업:

- B1. Supplemental Page Table Core
- B3. Uninit + Lazy Executable Loading

핵심은 직접 새 유틸을 많이 만들기보다, Pintos가 이미 제공하는 함수와 매크로를 잘 쓰는 것이다.

---

## 1. 주소와 페이지 경계 처리

파일:

- `pintos/include/threads/vaddr.h`

### `PGSIZE`

한 페이지 크기다. Pintos에서는 보통 4096바이트다.

사용 위치:

- 한 페이지 단위로 `read_bytes`, `zero_bytes` 계산
- lazy load에서 한 페이지를 채울 때
- `aux`가 한 페이지에 필요한 정보만 들고 있는지 확인할 때

### `pg_round_down(va)`

주소를 그 페이지의 시작 주소로 내린다.

예:

```c
void *upage = pg_round_down (va);
```

B1에서 가장 중요하다.

SPT key는 fault가 난 정확한 주소가 아니라 page base 주소여야 한다.

예:

```text
fault 주소: 0x8048123
SPT key:   pg_round_down(0x8048123)
```

사용 위치:

- `spt_find_page()`
- `spt_insert_page()` 중복 검사
- `vm_claim_page()`

### `pg_round_up(va)`

주소를 다음 페이지 경계로 올린다.

B3에서는 보통 `load_segment()`에서 페이지 단위 반복을 만들 때 참고할 수 있다.

### `pg_ofs(va)`

주소가 페이지 안에서 몇 번째 바이트인지 구한다.

처음 B1/B3에서는 자주 쓰지 않아도 되지만, 이후 stack growth나 mmap boundary에서 유용하다.

### `is_user_vaddr(vaddr)`

주소가 user 영역인지 검사한다.

B1/B3 자체보다 B4 page fault에서 더 중요하지만, B3에서 이상한 주소를 SPT에 넣지 않도록 방어할 때도 쓸 수 있다.

## 2. SPT 구현에 쓰는 hash 함수

파일:

- `pintos/include/lib/kernel/hash.h`
- `pintos/lib/kernel/hash.c`

B1에서 SPT를 hash table로 만들 때 사용한다.

### `struct hash`

SPT 안에 넣을 hash table 타입이다.

예:

```c
struct supplemental_page_table {
    struct hash pages;
};
```

### `struct hash_elem`

hash table에 넣을 원소가 자기 안에 들고 있어야 하는 연결 고리다.

`struct page`에 추가하는 식으로 쓴다.

예:

```c
struct page {
    const struct page_operations *operations;
    void *va;
    struct frame *frame;
    struct hash_elem hash_elem;
    bool writable;
    ...
};
```

### `hash_init(hash, hash_func, less_func, aux)`

hash table을 초기화한다.

사용 위치:

```c
void
supplemental_page_table_init (struct supplemental_page_table *spt) {
    hash_init (&spt->pages, page_hash, page_less, NULL);
}
```

### `hash_bytes(data, size)`

바이트 배열을 hash 값으로 바꿔준다.

SPT에서는 `page->va`를 hash key로 쓰면 된다.

예:

```c
static uint64_t
page_hash (const struct hash_elem *e, void *aux UNUSED) {
    const struct page *page = hash_entry (e, struct page, hash_elem);
    return hash_bytes (&page->va, sizeof page->va);
}
```

### `hash_entry(hash_elem, struct_type, member)`

`struct hash_elem *`에서 실제 바깥 구조체 포인터를 꺼낸다.

예:

```c
struct page *page = hash_entry (e, struct page, hash_elem);
```

SPT에서 거의 필수다.

### `hash_find(hash, elem)`

같은 key를 가진 원소를 찾는다.

`spt_find_page()`에서 임시 page를 하나 만들어 key만 채운 뒤 찾는 방식이 흔하다.

예:

```c
struct page temp;
temp.va = pg_round_down (va);

struct hash_elem *e = hash_find (&spt->pages, &temp.hash_elem);
if (e == NULL)
    return NULL;

return hash_entry (e, struct page, hash_elem);
```

### `hash_insert(hash, elem)`

새 원소를 넣는다.

이미 같은 key가 있으면 기존 원소를 반환한다. 성공하면 `NULL`을 반환한다.

예:

```c
bool
spt_insert_page (struct supplemental_page_table *spt, struct page *page) {
    return hash_insert (&spt->pages, &page->hash_elem) == NULL;
}
```

### `hash_delete(hash, elem)`

원소를 hash table에서 제거한다.

사용 위치:

- `spt_remove_page()`
- insert 실패 rollback
- process exit cleanup

### `hash_destroy(hash, action)`

hash table을 없애면서 각 원소마다 action을 실행한다.

B6에서 더 중요하지만, B1에서 미리 구조를 알고 있으면 좋다.

## 3. 현재 스레드와 현재 SPT 찾기

파일:

- `pintos/include/threads/thread.h`
- `pintos/threads/thread.c`

### `thread_current()`

현재 실행 중인 thread를 반환한다.

Project 3에서 user process 하나는 보통 kernel thread 하나다.
그래서 현재 프로세스의 SPT는 아래처럼 접근한다.

```c
struct supplemental_page_table *spt = &thread_current ()->spt;
```

사용 위치:

- `vm_alloc_page_with_initializer()`
- `vm_claim_page()`
- `vm_try_handle_fault()`

주의:

SPT는 프로세스별 자료구조다.
반대로 frame table은 시스템 전체 자료구조라 전역으로 둔다.

## 4. 메모리 할당과 해제

파일:

- `pintos/include/threads/malloc.h`
- `pintos/include/threads/palloc.h`

### `malloc(size)` / `free(ptr)`

작은 커널 구조체를 만들 때 쓴다.

B1/B3에서 주로 쓰는 대상:

- `struct page`
- lazy load용 `aux`

예:

```c
struct page *page = malloc (sizeof *page);
if (page == NULL)
    goto err;
```

### `palloc_get_page(flags)` / `palloc_free_page(kva)`

4KB 페이지 단위 물리 메모리를 얻거나 돌려준다.

B3에서는 직접 많이 쓰기보다, B2의 `vm_get_frame()`이 `palloc_get_page(PAL_USER)`를 사용한다.

그래도 기존 Project2 `setup_stack()`이나 `load_segment()`를 읽을 때 자주 보인다.

### `PAL_USER`

user process가 쓸 물리 페이지를 user pool에서 가져오라는 뜻이다.

B2에서 중요하다.

### `PAL_ZERO`

할당받은 페이지를 0으로 초기화한다.

기존 Project2 코드나 stack setup을 읽을 때 나온다.

## 5. VM page 생성과 초기화 흐름

파일:

- `pintos/include/vm/vm.h`
- `pintos/vm/vm.c`
- `pintos/include/vm/uninit.h`
- `pintos/vm/uninit.c`
- `pintos/vm/anon.c`
- `pintos/vm/file.c`

### `vm_alloc_page_with_initializer(type, upage, writable, init, aux)`

B3의 핵심 함수다.

이 함수가 해야 하는 일:

```text
1. upage가 이미 SPT에 있는지 확인
2. struct page를 malloc
3. type에 맞는 initializer 선택
4. uninit_new() 호출
5. writable 같은 추가 필드 설정
6. spt_insert_page()로 SPT에 넣기
```

추천 흐름:

```c
if (spt_find_page (spt, upage) == NULL) {
    struct page *page = malloc (sizeof *page);
    if (page == NULL)
        goto err;

    bool (*initializer)(struct page *, enum vm_type, void *) = NULL;
    switch (VM_TYPE (type)) {
        case VM_ANON:
            initializer = anon_initializer;
            break;
        case VM_FILE:
            initializer = file_backed_initializer;
            break;
    }

    uninit_new (page, upage, init, type, aux, initializer);
    page->writable = writable;

    if (spt_insert_page (spt, page))
        return true;

    free (page);
}
```

### `VM_TYPE(type)`

marker bit를 제외하고 실제 page type만 꺼낸다.

예:

```c
switch (VM_TYPE (type)) {
    case VM_ANON:
    case VM_FILE:
}
```

B3에서 initializer를 고를 때 유용하다.

### `uninit_new(page, va, init, type, aux, initializer)`

page를 아직 실제 내용이 없는 lazy page로 만든다.

중요한 점:

- 처음에는 `page->operations = &uninit_ops`
- 실제 타입은 `page->uninit.type`에 저장됨
- 첫 page fault 때 `uninit_initialize()`가 진짜 initializer를 호출함

### `swap_in(page, kva)`

page 타입에 맞는 `swap_in` 함수를 호출한다.

B3 lazy page에서는 처음 `swap_in()`이 호출되면 내부적으로 `uninit_initialize()`가 실행된다.

즉, 흐름은 이렇게 이어진다.

```text
vm_do_claim_page()
-> swap_in(page, frame->kva)
-> uninit_initialize()
-> anon_initializer() 또는 file_backed_initializer()
-> lazy_load_segment()
```

### `page_get_type(page)`

현재 page의 실제 타입을 알고 싶을 때 쓴다.

`VM_UNINIT` page여도 내부에 저장된 예정 타입을 꺼내준다.

## 6. 파일 읽기와 lazy load에 쓰는 함수

파일:

- `pintos/include/filesys/file.h`
- `pintos/filesys/file.c`

### `file_read_at(file, buffer, size, start)`

파일의 특정 offset에서 읽는다.

B3의 `lazy_load_segment()`에서 가장 유용하다.
`file_seek()` 후 `file_read()`를 쓰는 것보다 위치가 명확하다.

예:

```c
if (file_read_at (aux->file, kva, aux->read_bytes, aux->ofs)
        != (off_t) aux->read_bytes) {
    return false;
}
```

### `file_seek(file, ofs)` / `file_read(file, buffer, size)`

기존 skeleton이나 Project2 코드에서 자주 쓰는 방식이다.

lazy load에서는 `file_read_at()`이 더 읽기 쉽다.

### `file_reopen(file)`

같은 inode를 가리키는 새 file 객체를 만든다.

B3 executable lazy loading에서는 팀 정책에 따라 나중에 필요할 수 있다.
특히 mmap 단계에서는 file lifetime 때문에 중요해진다.

### `file_close(file)`

file 객체를 닫는다.

주의:

aux에 file을 넣었다면 언제 닫을지 정책이 필요하다.
B3 초반에는 aux free만 먼저 정리하고, file close 정책은 executable/mmap 흐름을 구분해서 잡는 것이 좋다.

## 7. 메모리 복사와 0 채우기

파일:

- `pintos/include/lib/string.h`

### `memset(ptr, 0, size)`

메모리를 0으로 채운다.

B3의 `lazy_load_segment()`에서 파일을 읽고 남은 부분을 0으로 채울 때 쓴다.

예:

```c
memset ((uint8_t *) kva + aux->read_bytes, 0, aux->zero_bytes);
```

### `memcpy(dst, src, size)`

메모리 내용을 복사한다.

B3보다는 fork/SPT copy에서 더 자주 쓰지만, 기존 Project2 코드를 읽을 때 나온다.

## 9. assertion과 방어 코드

파일:

- `pintos/include/lib/debug.h`

### `ASSERT(condition)`

조건이 거짓이면 커널 panic을 낸다.

개발 중에는 함수 계약을 확인하는 데 좋다.

예:

```c
ASSERT (page != NULL);
ASSERT (pg_ofs (page->va) == 0);
```

주의:

사용자 입력 때문에 실패할 수 있는 조건에는 `ASSERT`보다 정상 실패 처리를 해야 한다.

### `PANIC("message")`

절대 일어나면 안 되는 커널 내부 오류에 쓴다.

B1/B3 일반 실패 처리에는 보통 쓰지 않는 것이 좋다.

## 10. B1에서 특히 자주 쓰는 조합

### SPT 초기화

```c
hash_init (&spt->pages, page_hash, page_less, NULL);
```

### SPT lookup

```c
struct page temp;
temp.va = pg_round_down (va);
struct hash_elem *e = hash_find (&spt->pages, &temp.hash_elem);
```

### SPT insert

```c
page->va = pg_round_down (page->va);
return hash_insert (&spt->pages, &page->hash_elem) == NULL;
```

### SPT remove

```c
hash_delete (&spt->pages, &page->hash_elem);
vm_dealloc_page (page);
```

## 11. B3에서 특히 자주 쓰는 조합

### lazy aux 예시

```c
struct lazy_load_arg {
    struct file *file;
    off_t ofs;
    size_t read_bytes;
    size_t zero_bytes;
};
```

### load_segment에서 aux 만들기

```c
struct lazy_load_arg *aux = malloc (sizeof *aux);
aux->file = file;
aux->ofs = ofs;
aux->read_bytes = page_read_bytes;
aux->zero_bytes = page_zero_bytes;
```

### uninit page 예약

```c
vm_alloc_page_with_initializer (VM_ANON, upage, writable,
        lazy_load_segment, aux);
```

### lazy_load_segment에서 실제 로드

```c
struct lazy_load_arg *aux = aux_;

if (file_read_at (aux->file, kva, aux->read_bytes, aux->ofs)
        != (off_t) aux->read_bytes) {
    free (aux);
    return false;
}

memset ((uint8_t *) kva + aux->read_bytes, 0, aux->zero_bytes);
free (aux);
return true;
```

## 12. B1/B3 구현 시 가장 중요한 규칙

1. `page->va`는 항상 `pg_round_down(va)`로 저장한다.
2. SPT key도 항상 page base 주소다.
3. `vm_alloc_page_with_initializer()`는 page를 만들고 SPT에 예약만 한다.
4. 실제 파일 읽기는 첫 page fault 이후 `lazy_load_segment()`에서 한다.
5. `aux`는 page마다 따로 만든다.
6. `aux`는 lazy load가 끝나면 반드시 free한다.
7. `struct page`는 `malloc`, 실제 frame은 B2의 `vm_get_frame()`에서 `palloc_get_page(PAL_USER)`로 얻는다.
