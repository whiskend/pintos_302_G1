# B2/B4 구현용 Pintos 헬퍼 함수 정리

대상 작업:

- B2. Frame + Claim Minimal
- B4. Page Fault Core / Protection

핵심은 두 가지다.

1. B4에서 page fault가 정상적인 fault인지 먼저 판단한다.
2. 정상 fault라면 B2의 claim 흐름으로 넘겨 실제 frame을 붙인다.

---

## 1. 전체 흐름에서 쓰이는 함수

### `page_fault(struct intr_frame *f)`

파일:

- `pintos/userprog/exception.c`

CPU가 page fault를 발생시키면 처음 들어오는 함수다.

여기서 하는 일:

- fault가 난 주소를 얻는다.
- fault 원인을 해석한다.
- Project 3에서는 `vm_try_handle_fault()`로 처리를 넘긴다.
- 처리 실패 시 프로세스를 종료한다.

흐름:

```text
page_fault()
  -> rcr2()로 fault_addr 확인
  -> f->error_code로 원인 확인
  -> vm_try_handle_fault()
  -> 성공하면 return
  -> 실패하면 exit(-1) 또는 kill
```

---

### `vm_try_handle_fault(struct intr_frame *f, void *addr, bool user, bool write, bool not_present)`

파일:

- `pintos/vm/vm.c`

B4의 중심 함수다.

여기서 판단할 것:

- `addr`가 NULL인지
- `addr`가 user address인지
- `not_present` fault인지
- write fault인데 해당 page가 writable인지
- SPT에 등록된 page인지
- stack growth 대상인지

처리 가능한 fault라면 마지막에 claim을 호출한다.

```text
vm_try_handle_fault()
  -> 주소 검증
  -> 권한 검증
  -> spt_find_page()
  -> page가 있으면 vm_do_claim_page()
```

---

### `vm_claim_page(void *va)`

파일:

- `pintos/vm/vm.c`

B2에서 쓰는 public claim 함수다.

역할:

- `va`에 해당하는 page를 SPT에서 찾는다.
- 찾은 page를 실제 메모리에 올린다.

보통 흐름:

```text
vm_claim_page(va)
  -> spt_find_page(&thread_current()->spt, va)
  -> vm_do_claim_page(page)
```

---

### `vm_do_claim_page(struct page *page)`

파일:

- `pintos/vm/vm.c`

B2의 핵심 함수다.

역할:

- 실제 frame을 얻는다.
- `page`와 `frame`을 서로 연결한다.
- page table에 `page->va -> frame->kva` 매핑을 넣는다.
- page 타입에 맞게 내용을 채운다.

흐름:

```text
vm_do_claim_page(page)
  -> vm_get_frame()
  -> frame->page = page
  -> page->frame = frame
  -> pml4_set_page()
  -> swap_in(page, frame->kva)
```

---

### `vm_get_frame(void)`

파일:

- `pintos/vm/vm.c`

실제 물리 메모리 한 페이지를 가져오는 함수다.

초반 구현에서는 보통 `palloc_get_page(PAL_USER)`를 사용한다.

나중에 메모리가 부족하면 `vm_evict_frame()`으로 넘어가야 한다.

---

## 2. 주소 처리 헬퍼

파일:

- `pintos/include/threads/vaddr.h`

### `PGSIZE`

한 페이지 크기다.

Pintos에서는 보통 4096바이트다.

사용 위치:

- frame 하나의 크기
- page 하나의 크기
- stack limit 계산
- page boundary 계산

---

### `pg_round_down(va)`

주소를 그 페이지의 시작 주소로 내린다.

B2/B4에서 매우 자주 쓴다.

예:

```text
fault addr: 0x8048123
page addr:  0x8048000
```

사용 위치:

- `spt_find_page()`
- `vm_claim_page()`
- `vm_try_handle_fault()`

fault 주소는 페이지 중간일 수 있다. SPT는 페이지 시작 주소 기준으로 찾는 것이 안전하다.

---

### `pg_round_up(va)`

주소를 다음 페이지 경계로 올린다.

B2/B4에서는 필수는 아니지만, stack growth나 mmap 경계 검사에서 유용하다.

---

### `pg_ofs(va)`

주소가 페이지 안에서 몇 번째 바이트인지 알려준다.

사용 위치:

- 정렬 여부 확인
- mmap offset 검사
- page boundary 디버깅

---

### `is_user_vaddr(vaddr)`

주소가 user 영역인지 확인한다.

B4에서 중요하다.

사용 위치:

- kernel address 접근 차단
- 잘못된 fault 주소 차단

---

### `is_kernel_vaddr(vaddr)`

주소가 kernel 영역인지 확인한다.

`is_user_vaddr()`의 반대라고 보면 된다.

B4에서 kernel address를 user process가 건드리는 경우를 막을 때 쓸 수 있다.

---

### `USER_STACK`

user stack의 시작 주소다.

B4 자체보다는 B5 stack growth에서 더 중요하다.

다만 B4에서 fault 주소가 stack 근처인지 판단하려면 같이 보게 된다.

---

## 3. page fault 원인 해석 헬퍼

파일:

- `pintos/include/userprog/exception.h`
- `pintos/userprog/exception.c`
- `pintos/include/intrinsic.h`

### `rcr2()`

page fault가 난 가상 주소를 읽는다.

`exception.c`의 `page_fault()`에서 이미 사용 중이다.

```c
fault_addr = (void *) rcr2 ();
```

주의:

- CR2 값은 page fault 주소다.
- 현재 실행 중이던 명령어 주소는 `f->rip`이다.
- 둘은 다를 수 있다.

---

### `PF_P`

page fault의 present bit다.

`exception.c`에서는 이렇게 해석한다.

```c
not_present = (f->error_code & PF_P) == 0;
```

의미:

- `not_present == true`: 아직 페이지가 물리 메모리에 없음
- `not_present == false`: 이미 매핑된 페이지인데 권한 위반 발생

B4에서는 보통 `not_present == true`인 경우만 lazy loading으로 살릴 수 있다.

---

### `PF_W`

쓰기 접근 때문에 fault가 났는지 알려준다.

```c
write = (f->error_code & PF_W) != 0;
```

의미:

- `write == true`: 쓰기 접근
- `write == false`: 읽기 접근

B4에서 read-only page에 write한 경우를 잡을 때 필요하다.

---

### `PF_U`

user mode에서 발생한 fault인지 알려준다.

```c
user = (f->error_code & PF_U) != 0;
```

의미:

- `user == true`: user process가 접근하다가 fault
- `user == false`: kernel mode에서 fault

Project 3에서는 syscall 중 kernel mode에서 user pointer를 만지다가 fault가 날 수도 있다.

---

### `struct intr_frame`

파일:

- `pintos/include/threads/interrupt.h`

page fault 당시의 레지스터 상태가 들어 있다.

B4에서 주로 보는 필드:

- `f->error_code`: fault 원인
- `f->rsp`: user stack pointer
- `f->rip`: fault가 발생한 명령어 주소

초반 B4에서는 `error_code`가 가장 중요하다.

stack growth까지 가면 `rsp`가 중요해진다.

---

## 4. frame 할당 헬퍼

파일:

- `pintos/include/threads/palloc.h`
- `pintos/threads/palloc.c`

### `palloc_get_page(flags)`

물리 메모리에서 페이지 하나를 가져온다.

B2에서는 반드시 user pool에서 받아야 한다.

```c
void *kva = palloc_get_page (PAL_USER);
```

중요:

- `PAL_USER` 없이 받으면 kernel pool에서 가져온다.
- Project 3의 user page frame은 `PAL_USER`를 써야 한다.

---

### `PAL_USER`

user pool에서 페이지를 할당하라는 flag다.

B2의 `vm_get_frame()`에서 핵심이다.

---

### `PAL_ZERO`

할당받은 페이지를 0으로 채운다.

익명 페이지나 stack page에서 유용하다.

단, lazy executable loading에서는 파일 내용을 읽은 뒤 남은 부분만 0으로 채우는 흐름도 있으므로 상황에 맞게 쓴다.

---

### `palloc_free_page(page)`

할당받은 물리 페이지를 되돌려준다.

B2 rollback에서 중요하다.

사용 상황:

- frame 구조체 할당은 성공했지만 `pml4_set_page()` 실패
- `swap_in()` 실패
- 중간에 claim이 실패해서 frame을 버려야 할 때

---

## 5. frame table에 쓰는 자료구조 헬퍼

파일:

- `pintos/include/lib/kernel/list.h`

### `struct list`

frame table을 전역 리스트로 관리할 때 쓸 수 있다.

예상 구조:

```c
static struct list frame_table;
```

---

### `struct list_elem`

리스트에 들어갈 구조체가 자기 안에 가져야 하는 연결 고리다.

frame table을 list로 만들면 `struct frame` 안에 넣는다.

```c
struct frame {
    void *kva;
    struct page *page;
    struct list_elem elem;
};
```

---

### `list_init(list)`

리스트를 초기화한다.

frame table은 보통 `vm_init()`에서 초기화한다.

---

### `list_push_back(list, elem)`

리스트 뒤에 원소를 추가한다.

새 frame을 만들었을 때 frame table에 넣는 데 쓴다.

---

### `list_remove(elem)`

리스트에서 원소를 제거한다.

frame을 해제하거나 eviction 후 정리할 때 쓴다.

---

### `list_entry(elem, struct_type, member)`

`struct list_elem *`에서 실제 구조체 포인터를 꺼낸다.

frame table 순회나 victim 선택에서 필요하다.

---

## 6. frame table lock 헬퍼

파일:

- `pintos/include/threads/synch.h`

frame table은 여러 thread가 함께 접근할 수 있는 전역 자료구조다.

따라서 frame table을 수정할 때는 lock을 두는 것이 안전하다.

### `struct lock`

전역 lock으로 둘 수 있다.

```c
static struct lock frame_table_lock;
```

---

### `lock_init(lock)`

lock을 초기화한다.

보통 `vm_init()`에서 frame table과 함께 초기화한다.

---

### `lock_acquire(lock)`

공유 자료구조에 접근하기 전에 lock을 잡는다.

사용 위치:

- frame table insert
- frame table remove
- victim 선택

---

### `lock_release(lock)`

작업이 끝나면 lock을 푼다.

주의:

- lock을 잡은 상태에서 오래 걸리는 파일 I/O를 하면 위험할 수 있다.
- B2 초반에는 insert/remove 범위를 짧게 잡는 것이 좋다.

---

## 7. page table 매핑 헬퍼

파일:

- `pintos/include/threads/mmu.h`
- `pintos/threads/mmu.c`

### `pml4_set_page(pml4, upage, kpage, rw)`

사용자 가상 주소 `upage`를 커널 가상 주소 `kpage`에 매핑한다.

B2의 `vm_do_claim_page()`에서 핵심이다.

```text
upage: page->va
kpage: frame->kva
rw: page가 writable이면 true
```

주의:

- `upage`는 user virtual address여야 한다.
- `upage`는 페이지 시작 주소여야 한다.
- 이미 매핑된 주소면 실패할 수 있다.

---

### `pml4_get_page(pml4, upage)`

가상 주소가 이미 매핑되어 있는지 확인한다.

사용 위치:

- 중복 매핑 방지
- 디버깅
- syscall pointer check

초반 B2에서는 `pml4_set_page()` 전에 이미 매핑된 주소인지 확인할 때 참고할 수 있다.

---

### `pml4_clear_page(pml4, upage)`

가상 주소의 매핑을 제거한다.

B2 rollback에서 유용하다.

예:

```text
pml4_set_page()는 성공했는데 swap_in() 실패
  -> pml4_clear_page()
  -> frame/page 연결 정리
```

---

### `pml4_is_dirty(pml4, upage)`

페이지가 수정되었는지 확인한다.

B2/B4보다는 B10 file-backed writeback에서 더 중요하다.

지금은 이름만 알아두면 된다.

---

### `pml4_is_accessed(pml4, upage)`

페이지가 최근 접근되었는지 확인한다.

B7 eviction clock 알고리즘에서 중요하다.

B2 frame table을 설계할 때 나중에 쓰일 수 있다는 정도만 알아두면 된다.

---

## 8. page 내용 채우기 헬퍼

파일:

- `pintos/include/vm/vm.h`
- `pintos/vm/uninit.c`
- `pintos/vm/anon.c`
- `pintos/vm/file.c`

### `swap_in(page, kva)`

`page` 타입에 맞게 실제 내용을 `kva`에 채운다.

매크로 형태다.

```c
#define swap_in(page, v) (page)->operations->swap_in ((page), v)
```

B2의 `vm_do_claim_page()` 마지막에 호출된다.

타입별 흐름:

```text
VM_UNINIT
  -> uninit_initialize()
  -> anon_initializer() 또는 file_backed_initializer()
  -> lazy_load_segment()

VM_ANON
  -> anon_swap_in()

VM_FILE
  -> file_backed_swap_in()
```

초반 B3와 연결되는 지점이 바로 여기다.

---

### `page->operations`

page가 어떤 종류인지에 따라 사용할 함수 테이블이다.

중요한 멤버:

- `swap_in`
- `swap_out`
- `destroy`
- `type`

B2에서는 직접 많이 만지기보다 `swap_in(page, kva)` 매크로를 통해 사용한다.

---

### `page_get_type(page)`

page의 실제 타입을 얻는다.

`VM_UNINIT` page라도 내부에 최종 타입이 따로 저장되어 있으므로, 단순히 `page->operations->type`만 보는 것보다 안전하다.

사용 위치:

- 디버깅
- page fault에서 타입별 처리가 필요할 때
- stack marker 확인

---

## 9. 현재 thread와 SPT 접근 헬퍼

파일:

- `pintos/include/threads/thread.h`
- `pintos/threads/thread.c`

### `thread_current()`

현재 실행 중인 thread를 반환한다.

현재 프로세스의 SPT는 보통 이렇게 접근한다.

```c
struct supplemental_page_table *spt = &thread_current ()->spt;
```

B2/B4 둘 다 자주 쓴다.

---

### `thread_current()->pml4`

현재 프로세스의 page table이다.

B2에서 `pml4_set_page()`를 호출할 때 사용한다.

---

### `thread_current()->spt`

현재 프로세스의 supplemental page table이다.

B4에서 fault 주소가 등록된 page인지 확인할 때 사용한다.

---

## 10. B2에서 자주 나오는 rollback 지점

B2는 실패 처리가 중요하다.

특히 아래 순서를 의식하면 좋다.

```text
frame 할당 성공
  -> frame 구조체 생성 성공
  -> page/frame 연결
  -> pml4_set_page 성공
  -> swap_in 실패
```

중간에 실패하면 이미 해둔 일을 되돌려야 한다.

자주 쓰는 함수:

- `pml4_clear_page()`
- `palloc_free_page()`
- `free()`
- `list_remove()`

---

## 11. B4에서 실패로 봐야 하는 경우

B4의 `vm_try_handle_fault()`는 아무 fault나 살리면 안 된다.

보통 실패로 처리할 후보:

- `addr == NULL`
- `addr`가 kernel address
- `not_present == false`인데 write-protection fault
- SPT에 page가 없고 stack growth 조건도 아님
- write fault인데 page가 writable이 아님

처리 실패 시 `false`를 반환한다.

그러면 `exception.c`의 `page_fault()`가 기존 종료 흐름을 탄다.

---

## 12. B2/B4 최소 구현 순서

추천 순서:

1. `struct frame`에 frame table용 필드 추가
2. `vm_init()`에서 frame table과 lock 초기화
3. `vm_get_frame()`에서 `palloc_get_page(PAL_USER)` 사용
4. frame table insert 구현
5. `vm_claim_page()`에서 SPT lookup 구현
6. `vm_do_claim_page()`에서 page-frame 연결
7. `pml4_set_page()`로 매핑
8. `swap_in(page, frame->kva)` 호출
9. `vm_try_handle_fault()`에서 fault 주소 검증
10. SPT hit 시 claim 흐름 연결
11. invalid fault는 `false` 반환

처음 목표는 eviction 없이도 lazy loading page가 실제 메모리에 올라오는 것이다.

---

## 13. 한눈에 보는 연결

```text
exception.c
page_fault()
  -> rcr2()
  -> PF_P / PF_W / PF_U 해석
  -> vm_try_handle_fault()

vm.c
vm_try_handle_fault()
  -> is_user_vaddr()
  -> pg_round_down()
  -> spt_find_page()
  -> vm_do_claim_page()

vm.c
vm_do_claim_page()
  -> vm_get_frame()
  -> pml4_set_page()
  -> swap_in()

palloc/mmu
palloc_get_page(PAL_USER)
pml4_set_page()
pml4_clear_page()
```
